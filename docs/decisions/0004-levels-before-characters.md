# ADR-0004: v0.5 关卡优先策略（暂停哪吒/杨戬，先做 L002）

- **状态**：Accepted
- **日期**：2026-05-25
- **决策人**：用户
- **影响版本**：v0.5+（推翻原 ROADMAP "v0.4=哪吒+杨戬+第二关" 排序）
- **相关任务**：v0.5 L002 14 任务（A01-A04 + F01-F02 + C01 + D01-D07）

---

## 1. 背景与问题

原始 09_ROADMAP.md 规划：
- v0.4 = 哪吒 + 杨戬 + 第二关（"角色与关卡同步推进"）
- v0.5 = 女娲 + 第三关
- v0.6 = 盘古 + 整体平衡

但实际开发偏离了原计划：
- **v0.3 阶段**：实现了 修行者归位 + 孙悟空 v1（灵气版）
- **v0.4 阶段**：孙悟空 v1 被推翻，重做为 v2（4 主动技能 + 火眼金睛被动），占用了原 v0.4 的全部时间

到 v0.5 启动时，用户面临选择：
- **路径 A**：补做"哪吒+杨戬+第二关"（按原 ROADMAP），但 3 个独立大功能同时做风险高
- **路径 B**：拆分 — 先做关卡（无角色依赖），再做新角色

用户明确选择 **路径 B**，理由：
- 关卡设计可独立测试（用现有修行者/孙悟空跑通）
- 关卡架构（StageConfig 数据驱动 + StageTransition 生存模式过渡）是后续多关游戏的基础
- 单批次任务范围小，质量更可控

## 2. 决策

**v0.5 = L002 幽都鬼市关卡 + 关卡架构升级**，**推迟哪吒/杨戬到 v0.6**。

具体内容：
- v0.5 仅做关卡基础设施 + L002 第二关
- 哪吒 + 杨戬合并到 v0.6（与 L003 同步推进）
- v0.7+ 各项顺延

## 3. 候选方案

### 方案 A：按原 ROADMAP 全部推进（哪吒+杨戬+L002 同时做）
- 优点：版本一致性，单次 release 包含更多功能
- 缺点：3 个大功能并发开发风险高；任何一个 bug 阻塞整个 release；测试周期长

### 方案 B（选定）：拆分推进，关卡优先
- 优点：单次 release 焦点明确（仅 L002）；关卡架构早期落地为后续多关复用；用户能更快看到新内容
- 缺点：v0.5 角色阵容仍是 2 个（修行者+孙悟空），需向用户解释 ROADMAP 调整

### 方案 C：先做新角色（哪吒/杨戬），关卡延后
- 优点：角色更新对玩家吸引力大
- 缺点：v0.4 已经在角色上投入了全部时间（孙悟空 v2），连续 2 个版本只做角色不做关卡 → 玩法循环单调

## 4. 选定方案与理由

**选 B**。理由：

1. **架构先行价值高**：StageConfig 数据驱动 + StageRegistry 关卡链 + StageTransition 过渡机制是后续所有关卡（L003/L004）的基础，越早落地越好
2. **生存模式塑造**：本次决定将主菜单流程从"角色选择 → 关卡选择 → 战斗"简化为"角色选择 → 战斗（生存模式自动推进关卡）"，与 Vampire Survivors 类型定位一致
3. **风险可控**：14 任务全部完成在 1 个 session 内（pm-planner 预估 7-8 session，实际加速完成），质量可保证
4. **后续灵活**：v0.6 可以根据 v0.5 实测反馈决定先做哪吒还是杨戬，或两者并行

## 5. 影响与后果

### 5.1 正面影响

- 玩家获得真正的"多关卡生存"体验（L001 → L002 自动过渡）
- 引入了 6 种新敌人（灯笼鬼/鬼差/怨婴/妖僧残念/镜妖精英 + 鬼市判官 Boss）
- 引入了远程攻击基础设施（RangedEnemy + EnemyProjectile）- v0.6 直接复用
- 引入了关卡过渡机制（不切场景 + 黑屏淡入 + StageConfig 热切）- 后续关卡复用
- StageDirector 数据驱动重构 - 添加新关卡 = 添加 .tres 文件，无需代码改动

### 5.2 负面影响 / 代价

- v0.5 角色阵容仍是 2 个（修行者 + 孙悟空），玩家可能期待新角色
- ROADMAP 后续版本号需顺延（v0.6 接管原 v0.5 内容 + 原 v0.4 推迟内容）
- L003 昆仑残境推到 v0.7（原 v0.5 内容），元素系统也顺延
